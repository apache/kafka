### Transformations applied (data-driven, from `migration-data.json`)

The scanner found **0 Category A** (removed setter accessors), **3 Category B**
(changed-return-type getters — all false positives, see below), and **15 Category C**
(Groovy DSL operator mutations) hits. All 15 Cat-C hits were real and rewritten — kind
`list` (`ListProperty<String>`):

- `org.gradle.api.tasks.compile.CompileOptions.compilerArgs` (`options.compilerArgs`):
  `<< "x"` → `.add("x")`, and `+= ["a", "b"]` → `.addAll([...])`. A chained

- `org.gradle.language.scala.tasks.BaseScalaCompileOptions.additionalParameters`
  (`scalaCompileOptions.additionalParameters`): `+= ["x"]` → `.add("x")`,
  `+= [a, b]` → `.addAll([...])`, `+= listVar` → `.addAll(listVar)`.

The pre-existing plain assignment `scalaCompileOptions.additionalParameters = [...]`
(line 781) and `options.release = releaseVersion` were left unchanged: Gradle's Groovy DSL
lazy-property assignment translates `prop = value` to `prop.set(value)` for `Property`/
`ListProperty`, so these still work (the scanner correctly did not flag them).

### Manual fixes beyond the migration data

One fix was required by the **baseline 9.4.1 → 9.5.1 upgrade** (task 03), unrelated to the
Provider API data: 8 cross-project references of the form `project(':x').sourceSets...`
(in dependency blocks) failed with *"Could not get unknown property 'sourceSets' … of type
DefaultProjectDependency"*. In Gradle 9.5 the `project(...)` dependency-block helper returns
a `ProjectDependency` that no longer exposes the target `Project`'s `sourceSets`. Each site
was rewritten to `rootProject.project(':x').sourceSets...`, which resolves the actual
`Project` and preserves the original cross-project source-set output access. After this fix
`./gradlew help` succeeded on Gradle 9.5.1.

`./gradlew help` (task 07) and `./gradlew assemble` (task 08) both passed on the first
attempt against the Provider API preview distribution, with no further edits needed.
